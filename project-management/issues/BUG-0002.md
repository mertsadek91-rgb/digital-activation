## Expected

Production refuses to boot without a strong fingerprint salt, as it refuses `KEK_PROVIDER=local`.

## Actual

`apps/api/src/vault/kek.ts:221` falls back to `''`. `config/env.ts` does not validate the variable. With no salt, the `fingerprint` column is an unsalted digest of low-entropy keys — the attack the code comment itself describes.

## Caution for the fix

The salt must be identical for every row (it is what makes the unique index catch duplicates). If production rows were fingerprinted with an empty salt, adding a salt now silently breaks duplicate detection for them. The fix therefore starts with a read-only check of whether production has the variable set — which needs the owner, because it touches the production environment.
