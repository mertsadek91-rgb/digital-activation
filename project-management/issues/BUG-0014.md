## Scope: the legacy site only

This finding concerns the **old WordPress website**, which still serves the apex
domain. On 2026-09-29, `https://digital-activation.com/` answered from Hostinger
with `x-powered-by: PHP/8.1.34`. It does **not** describe the new Node.js
application.

## Verified context by context

| Context                                  | Applies?           | Evidence                                                                                                                                                                                                                  |
| ---------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A. Live WordPress site                   | **Yes (inferred)** | The 2026-09-08 SQL dump of this site holds keys and credentials in order notes, and the site is still live. The live database was not inspected.                                                                          |
| B. Local backup on the developer machine | Yes, separately    | See BUG-0015.                                                                                                                                                                                                             |
| C. Git repository                        | **No**             | No `.sql`, `.sql.gz`, `.tar.gz`, `.wpress` or `Old Website/` path has ever been added, in HEAD or any branch (`git log --all --diff-filter=A`). `.gitignore` excludes them; CI runs gitleaks and a legacy-artefact guard. |
| D. New Node.js database                  | **No**             | On 2026-09-29, `vault."LicenseKey"` held 1 row, a test delivery. Legacy orders, customers and keys have not been imported (`import/index.ts:9-17`).                                                                       |
| E. New Node.js runtime                   | **No path**        | No runtime code reads `Old Website/` or the SQL dump. Only one-off scripts in `packages/db/scripts` read the XML export and the tarball, and they run on a developer machine.                                             |
| F. Deployment / Coolify                  | **No path**        | There is no Dockerfile. Coolify builds from the GitHub repository (`docs/deployment.md` §3), so only git-tracked files enter the build context. The storefront's `public/` holds only the logo.                           |

## Severity

**HIGH for the legacy system.** The site is live, public and runs PHP. Its
database holds customer secrets in plaintext, reachable through WordPress admin
accounts, the hosting account or a plugin compromise.

**Not CRITICAL, and not a finding against the new application.** It sets no
health status for the Node.js app. It becomes a cutover gate only once the owner
decides the migration scope (CONSENSUS-0002).

## Remediation (owner actions on the legacy system)

Until cutover: keep WordPress admin access to the minimum and rotate its
passwords.

The permanent fix is either the migration-and-scrub in TASK-0040, or retiring
the database when the site is switched off.
