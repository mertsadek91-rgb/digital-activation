## Actual

The doc comment on `AuthService.refresh` (apps/api/src/auth/auth.service.ts:310-316) says a replayed token revokes the whole session. The code rotates the hash in place; a replayed old token simply finds no row and gets 401. An attacker who captured a token and uses it first keeps a live session while the legitimate user is the one logged out.

Related (LOW): `POST /v1/auth/staff/refresh` carries no `@Throttle` (auth.controller.ts:97). The token has 384 bits of entropy, so this is hygiene, not an exploit.
