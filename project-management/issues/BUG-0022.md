# BUG-0022 — Checkout country select: hydration mismatch because the other-countries list is sorted with a locale collator over Intl.DisplayNames, whose order differs between Node and the browser

## Objective

Loading `/checkout` in `next dev --webpack` logged a React hydration mismatch inside the "other countries" `<optgroup>` of `CountrySelect`: the server (Node ICU) and the browser (its own ICU) sort the `Intl.DisplayNames` labels differently, so option _n_ was one country on the server and another on the client. Make the server and client agree without giving up the per-locale, alphabetical list and without adding a translation table.

## Notes

- Root cause is wider than the order. Once the order was deterministic, React still flagged `option[value=PS]`: Node names it الأراضي الفلسطينية / Palestinian Territories, current Chromium فلسطين / Palestine. `Intl` output cannot be rendered on the server and trusted to match the browser.
- Fix (`apps/storefront/src/components/country-select.tsx`): a `useHydrated()` hook on `useSyncExternalStore` (server snapshot `false`). Before hydration the select renders ISO codes in ISO-code order; after hydration the browser's `Intl.DisplayNames` and collation take over. The select is closed with the placeholder showing at that moment, so the swap is invisible; without JavaScript the list stays usable (codes).
- Verified 2026-10-05, dev server `storefront-webpack-3012` + mock API on :4000: fresh browser tab, `/ar/checkout` (RTL) and `/en/checkout`, console clean (only HMR). Server HTML: 13 + 54 options labelled by code. Client DOM: 54 collated names (ar: أذربيجان، إسبانيا، أستراليا…; en: Afghanistan, Albania, Argentina…). `pnpm typecheck` 15/15, `pnpm lint`, prettier: pass.
- Residual (owner's call, not taken here): country names now come from each shopper's browser, so PS/TR wording varies with the browser's CLDR release. A fixed wording would mean shipping the 67 names per locale in `messages/*.json`.
