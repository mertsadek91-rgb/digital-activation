# DEC-0011 — One environment, staging now, production later

## Observed

On 2026-09-29 the new stack answered on three hostnames:

| Service    | Hostname                       |
| ---------- | ------------------------------ |
| Storefront | `new.digital-activation.com`   |
| Admin      | `admin.digital-activation.com` |
| API        | `api.digital-activation.com`   |

The admin and API hostnames are the production names in `docs/deployment.md`.
The staging storefront calls the production-named API, and that API serves the
database the local `.env` reaches. No second environment is referenced anywhere
in the repository.

## Reading

The deployment is built to be promoted, not replaced. At cutover the storefront
moves to the apex, and the rest stays where it is.

## Consequence

Everything that must differ between staging and production has to change at
cutover, in one list. That list is TASK-0044.
