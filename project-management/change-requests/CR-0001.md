# CR-0001 — Activate the enterprise multi-agent governance constitution

## Original request

The owner supplied a master operating constitution defining an organisation of managers and specialists, authority levels 1–5, consensus governance, and a project-management system under `/project-management/`, with the instruction to run its initial activation procedure (inspect the repository, audit, create the structure, profiles, permissions, state files, dashboard and initial tasks, then begin controlled implementation).

## Objective

Give the rebuild an auditable organisational memory and a single place to see what is in flight, what is blocked and why — without adding a second source of truth that can drift.

## Scope

- In: the `project-management/` tree, its sync tool and dashboard, the current-state audit, verified issue records, corrective tasks, decision history reconstructed from the approved plan.
- In (Level 3, shared config): lint/format/ignore rules so the new tree does not break CI, and a `pm:sync` script.
- Out: any change to application code. Findings become tasks; implementation waits for the owner’s review of this CR.

## Impact areas

Repository config only (eslint ignores, prettier ignores for generated files, .gitignore exception for logs, a root script). No runtime, schema, API or UI change.

## Consensus requirement

None for the CR itself (Level 3). Two Level 5 items it surfaced are opened as CONSENSUS-0001 and CONSENSUS-0002.

## Tasks created

TASK-0001, TASK-0002, TASK-0003, and the corrective tasks listed against each BUG record.

## Final result
