# CR-0002 — Corrected project context and re-audit

## Original request

The owner stopped all fix work and corrected the context:

- WordPress is the old website, and its files are a backup and a migration
  source.
- The new Node.js application is already published to GitHub, deployed through
  Coolify, and running as a test version on the agreed domains.

The owner asked for a full read-only re-discovery. Every finding and task is to
be re-verified against code, and each finding must say which context it
affects: the legacy site, migration data, local backups, the new application,
or the deployment.

## What changed as a result

- The phase moved from "before cutover" to **staging live; validation before
  production cutover**.
- The health rule now covers only the new application and its infrastructure.
  LEGACY_WORDPRESS and MIGRATION findings are counted separately.
- BUG-0014 was split by context and moved from CRITICAL to HIGH, scoped to the
  legacy site. BUG-0015 (local backup) and BUG-0016 (staging becomes production
  in place) were added.
- Severities were lowered on BUG-0002, -0003, -0005 and -0006, each with its
  evidence.
- TASK-0003 was cancelled as based on a wrong assumption. TASK-0004, -0043 and
  -0044 were added. Eleven tasks were rewritten.

## Constraints observed

No application code, schema, environment, Coolify, Git history or data was
changed. Nothing was committed, pushed or deleted.

## Final result

Pending owner review.
