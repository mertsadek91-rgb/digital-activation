- **Task:** TASK-0044 (L4, release-manager). **Related:** DEC-0011, BUG-0016,
  CR-0002, TASK-0032 (cutover runbook), CONSENSUS-0001 (payment line-up),
  TASK-0043 (legacy data).
- **Status of this document:** a plan. Nothing in it has been applied, and no
  environment value, Coolify setting or database row was read to write it.
  "Staging value class" is what the code and docs imply; every one is marked
  **verify** where the live value is not known from the repository.
- **Sources:** `.env.example`, `apps/api/src/config/env.ts`, a grep of
  `process.env` across `apps/`, `packages/` and `workers/`, and
  `docs/deployment.md` §3–§13.
- **Where it is applied:** `docs/deployment.md` §13, step C4.
- **Items:** 77 (A 14, B 15, C 6, D 11, E 7, F 7, G 6, H 11).

## How to read the tables

| Column          | Meaning                                                                                                         |
| --------------- | --------------------------------------------------------------------------------------------------------------- |
| When            | **Pre** = can be done before cutover day with no visible effect; **C4** = at cutover; **Post** = after          |
| Who             | Owner performs every Coolify, DNS, payment-provider and data change (§13). Agents may run read-only checks      |
| Rebuild/restart | **Rebuild** for `NEXT_PUBLIC_*` and anything read in `next.config.ts` (inlined at build); **restart** otherwise |

Resources: **SF** storefront, **AD** admin, **API** api, **JOBS** jobs worker.

## Notes found while writing this

- `VAULT_FINGERPRINT_SALT` (`vault/kek.ts:221`) and the `KEK_VERSION`
  fallback (`vault/kek.ts:41`) are read by the API from `process.env` but are
  not in the schema's `ENV_KEYS` (`config/env.ts:8-138`). On Coolify, which
  injects variables directly, they work; from the env file alone the API would
  silently not see the salt (the BUG-0020 pattern). Worth a check, not a
  cutover blocker.
- `APP_ENV`, `WEB_PUSH_*` and `DA_*_PASSWORD` are in `.env.example` but not
  read at runtime; none needs a production value.
- `MEILI_HOST` and `MEILI_MASTER_KEY` are parsed by the env schema
  (`config/env.ts:47-48`, optional since TASK-0035) but no code uses them;
  leave them unset in production.
