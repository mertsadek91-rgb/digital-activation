- **301, not 308.** Every generated category row is written `code: 301`
  (`packages/db/scripts/legacy/redirects.ts:231-233`); the create/update schema
  only accepts 301 or 302 (`packages/contracts/src/content.ts:193`). The
  storefront then answers it with Next's `permanentRedirect`, which is a
  **308** on the wire (`apps/storefront/src/lib/gone.ts:20-24, 44`). So "301"
  in the row, "308" in `curl`, by design.
- **One row covers both URL forms.** Evidence:
  - Plain form: the catch-all route calls
    `goneOrRedirect('/' + slug.join('/'))`
    (`apps/storefront/src/app/[locale]/[...slug]/page.tsx:102`), which looks the
    path up in the map (`gone.ts:30`).
  - Nested form `/collections/ويندوز-windows/windows-server-ويندوز-سيرفر/microsoft-sql-server/`:
    multi-segment, so it also lands in the catch-all, misses the direct lookup,
    and falls back to `legacyCategoryRedirect`, which re-asks for
    `/product-category/<last segment>` (`gone.ts:30, 65-68`).
  - Trailing slash: the storefront first strips it with its own 308 (crawl
    "308 (slash)"), and the API lookup also trims trailing slashes
    (`apps/api/src/content/content.service.ts:329`).
  - Percent-encoding and case: the API decodes and lower-cases before the
    unique-key lookup (`content.service.ts:66, 320-331`); the admin create
    path normalises the same way (`apps/api/src/content/redirects.service.ts:203-225`).
    The path is ASCII anyway.
  - Locale: `/en/...` keeps the locale prefix on the target (`gone.ts:41-42`).
- **Target exists.** `windows-server` is a seeded collection
  (`packages/db/prisma/seed.ts:168`), served by
  `apps/storefront/src/app/[locale]/collections/[slug]/page.tsx` via
  `ROUTES.collection` (`packages/contracts/src/constants.ts:22`). The importer
  already put the legacy "Microsoft SQL Server" category's products there
  (`packages/db/scripts/import/normalize.ts:238`). The redirect generator wrote
