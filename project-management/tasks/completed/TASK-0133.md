# TASK-0133 — Supplier sync: upload the supplier price list as an Excel (.xlsx) file - read with strikethrough and merged categories, same parser, safety refusals and stock switching as the Google read

## Objective

On 2026-10-24 Google blocked the supplier's sheet (Tikeys) for a Terms of Service
violation, so the hourly read fails with 403. The supplier will send the list as an
Excel file instead. Staff upload that .xlsx in the admin, and it goes through the same
sync run as the Google read.

## Acceptance criteria

1. `POST /v1/admin/supplier/upload` (ADMIN, CATALOG; `force` only ADMIN/OWNER) takes
   `{fileName, data: base64, force}` and returns the same `SupplierSyncResult` as a sync.
2. The .xlsx is read into the same grid shape, and `parseSheet` handles it unchanged:
   - header detection
   - merged categories
   - strikethrough on the name, from the cell font or from rich-text runs; partial strikes are flagged
   - prices, with Excel float noise rounded
   - the update date
3. The same guards as the Google read: shape refusal, the shrink/outage refusal unless a
   person forces it, the advisory lock, a snapshot and audit, and stock reconciliation.
4. Hostile or wrong files are refused with a readable ar/en reason and change nothing:
   - .xls, CSV, an empty file or a non-zip
   - a file over 1.4 MiB
   - a zip bomb (bounded by the declared size, and checked against a lying size)
   - a DOCTYPE or entity part
   - a cell beyond 20000 rows or 200 columns
5. Every upload is audited with the file name, its size and its sha256.
6. Admin: a button beside "Read the sheet now", a client-side size check, a forced re-apply
   of a refused file, and a note while the hourly Google read is still on. Checked in ar
   (RTL) and en at 1440/1024/768/390/360.

## Notes

- No new database tables or migrations. New dependency: fflate 0.8.3, with no
  dependencies of its own. fast-xml-parser is already in the catalogue.
- Base64 JSON matches the media uploads. The API's 2 MiB body limit covers 1.4 MiB once encoded.
- Not CSV: a CSV loses the strikethrough, which carries the stock state.
- The integration suite caught an index shift from empty `<font/>` / `<si/>` elements.
  It is fixed, and a unit test covers it.
- Hardened after REV-0185/0186/0187, because parsing runs on the event loop and a
  third party's file must not stall the API. The caps:
  - 4 MiB unpacked
  - a part that is larger packed than its declared size is refused
  - 20 tabs, with each part parsed once
  - 200,000 cells, a budget shared with merged areas; merges are cut at the last row with a value
  - 2,000 characters per cell, and 2,000,000 characters of text in total, counted per use of a shared string
  - parser errors and UTF-16 parts are refused

  Measured worst cases still allowed: about 1 s for an empty-cell sheet that the cell cap
  then refuses, and about 0.2 s for maximum text.

- Force is offered only after a refusal seen on the page; after a reload the page cannot
  tell a sheet refusal from a file refusal.
- Known LOW items left: number formats are not applied, so a date stored as a number
  reads as its serial (the supplier writes the update date as text). The force rule on the
  HTTP route has no automated test, because the harness has no staff HTTP session.
