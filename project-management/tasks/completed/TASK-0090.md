# TASK-0090 — Apply the licensed Envato (MediCore) admin template design system to the whole admin panel

## Objective

The owner bought the MediCore admin template on Envato (licence certificate
6EB7W3PXGL, kept with the template under `Old Website/Template/`, which stays
outside the repo) and asked for its UI/UX to be applied professionally to every
admin screen. The template is static Bootstrap HTML; the admin is Next.js with
its own class vocabulary, Arabic-first and right-to-left, with an English mirror.

## What was done

- **Tokens** (`apps/admin/src/app/theme.css`): the template's palette, type scale,
  4px spacing, radii, shadows and layout sizes, defined on both the storefront
  token names the page styles already use and the template's own names. Light
  and dark themes; dark is a real elevation scale, not an inversion. The
  template's muted grey was darkened to clear WCAG AA (4.5:1) for small text.
  Inter serves the English panel (via `next/font`), Tajawal stays the Arabic face.
- **Components** (`components.css`): buttons, forms, badges with a status dot,
  alerts, cards, tables with the uppercase muted header, tabs, chips, segmented
  controls, pagination, page header, auth card — under the class names every
  screen already uses, so no screen had to be rewritten.
- **Shell** (`shell.css`, `nav.tsx`, `icons.tsx`, `theme-provider.tsx`): fixed
  sidebar with grouped navigation, inline SVG icon family, live badges, a
  collapsible icon rail (persisted), an off-canvas drawer under 992px with
  backdrop and Escape, a topbar with page title, language switch, theme toggle
  and an account menu. The theme is a cookie read by the root layout so the
  first paint is already right.
- **Screens**: dashboard stat cards with icons and trend chips; auth screens with
  the brand mark; `admin.css` rebuilt from the page-specific rules only — the
  layered `!important` refinement blocks, dead card styles and duplicated
  dashboard blocks were removed. Customer name and email now sit on one line
  with a hairline between them (owner request during the task).
- **Verification tooling**: `apps/admin/mock/api.mjs` (launch config
  `admin-mock-api`) serves contract-shaped fixtures so the panel can be rendered
  without the real API, which must never run against the staging database.

## Verification

- `tsc --noEmit`, ESLint and Prettier clean for the admin app.
- Rendered against the fixture API at 1440/1024/768/390/360 in Arabic (RTL) and
  English, light and dark: dashboard, queue, orders, products, customers,
  messages, reviews, launch, marketing, categories, login, password, and the
  error state of vault/payments/redirects/promotions/content. No console
  errors; no horizontal overflow (a 360px overflow in the dashboard split grid
  was found and fixed with `minmax(min(22rem, 100%), 1fr)`; the same guard was
  applied to every auto-fit grid).
- Shell interactions checked in the browser: dark mode sets the cookie and the
  `data-theme` attribute, the rail collapses to 76px and persists, the account
  menu opens and closes on Escape and outside click.

## Notes

- The template's hardcoded light row tints were replaced with `color-mix` on
  the tokens so held/overdue rows stay readable in dark mode.
- Not changed: `packages/ui/src/tokens.css` (the storefront keeps its palette);
  the admin overrides the token values for itself only.
