## Problems discovered

- `--check` reported files stale right after a `--fix` run: task order followed the folder walk, so moving a file reordered every derived array.
- Prettier rewrites long YAML lists in front matter across several lines; the parser only read single-line lists, so the file-collision check was blind to tasks with more than three affected files (TASK-0002, TASK-0010, TASK-0018).
- An empty `key:` parsed as an empty list, which is truthy — a Level 5 task with no `related_consensus` would have passed the consensus rule.
- The first file collision the tool reported was real: TASK-0030, TASK-0032 and TASK-0070 all edit `docs/deployment.md`.
- Hand-written activity-log entries carried invented clock times later than the real sync time.

## Solutions applied

- Records are sorted by id at load, so output no longer depends on folder layout.
- The parser reads multi-line flow lists and turns an empty `key:` into null.
- The validator was then exercised on a scratch copy with one injected violation per rule; every one was reported and the run exited 1.
- pm-06 sequenced the three `deployment.md` tasks (COMMENT-0003 to COMMENT-0005).
- Retrospective log entries now carry the date only, with a note in the log header.
