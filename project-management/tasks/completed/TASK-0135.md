# TASK-0135 — Supplier prices tab: filter rows by current price against cost (below, at, above), and set a variant's markup in place from a percentage or a typed price, with pin-only and pin-and-apply

## Objective

The owner asked, on 2026-10-26, for two things on the supplier **Prices** tab:

1. Sort the products by where today's price stands against the supplier's cost: below cost, at cost, or above cost.
2. Change one product's markup on that same page. This can be done by typing the markup, or by typing the price wanted. When a price is typed, the system works out the markup and pins it to that product.

The owner chose:

- **Two buttons:** "Pin markup" saves the markup only. "Pin and apply" saves it and changes the store price immediately.
- **The filter uses the current price.** It compares the price customers pay today with the cost, not the proposed price.

## Acceptance criteria

- **Cost standing.** Each price row carries `costStanding` (`BELOW` / `AT` / `ABOVE`, or null when there is no cost).
  - It compares the current price with the cost, to the cent.
  - The tab filters on it, and every filter chip shows its count.
  - A below-cost row shows the loss per sale under its current price.
- **New endpoint.** `PUT /v1/admin/supplier/prices/:variantId/markup` is ADMIN only, like every money action on this controller. The body is exactly one of:
  - `markupPercent` (0 to 1000), or `null` to go back to the sheet's markup;
  - `targetPriceUsd`, which must be above the cost.
    It also accepts an optional `apply`.
- **Markup from a typed price.** The pinned markup is the two-decimal value whose proposal, under the source's rounding rule, lands nearest the typed price. On a tie, the value nearest the exact percentage wins.
  - Example: 13.37 on a 10.00 cost pins 33.70%, not 33.65%.
  - The markup is pinned, not the price. Later cost changes therefore keep the same margin.
- **Applying.** `apply` goes through `applyPrices`, with the guards it already has: never below cost, never a line missing from the sheet, never a line with no cost. Without `apply`, the store price does not move.
- **Audit.** Every change is audited as `supplier.markup_set`, with the before and after markup, the typed price, and the cost.
- **Rendering.** The page was checked at 1440, 768, 390 and 360, in Arabic (RTL) and English.
  - The editor stays fully visible on a phone, held at the edge while the wide table scrolls sideways.
  - No page overflow at any of those widths.

## Notes

- No schema change. `VariantSupplierLink.markupPercent` already held a per-variant override, which until now could only be set on the Mapping tab when linking.
- Tests:
  - unit: `markupForPrice` (each rounding rule, the tie-break, and targets off the rounding grid), `costStanding`, and the contract;
  - integration: pin without moving the price, pin and apply, reset to the sheet markup, refusal at or below cost, refusal for an unlinked variant, and the three cost standings.

## Review findings and what was done

- **REV-0199 (qa-lead), MED, nearest price.** Typed prices off the rounding grid did not land on the nearest price the rule allows.
  - `markupForPrice` now tries the prices the rounding rule can make on each side of the target, and picks the nearest. An even split goes up.
  - Brute force on 450 random cases: 0 misses.
- **REV-0199, MED, proposal at cost.** A typed price could pin a markup whose proposal is at or under cost (for example 1000.00 → 1000.01).
  - `markupForPrice` never chooses such a markup.
  - When only a markup over 1000% would do, it returns null and the API refuses.
- **REV-0196 (pm-03) MED / REV-0197 / REV-0199, large changes.** "Pin and apply" moved large changes with no warning.
  - The editor now previews the price under the source's rounding rule. `SupplierPrices` carries `rounding` (an additive field).
  - The preview flags a change over 30%, and "Pin and apply" asks for confirmation first.
  - The server path still passes `confirmLarge`, as the single-row Apply always has: one row is looked at on purpose.
- **REV-0197 / REV-0199, LOW, coercion.** `setVariantMarkupSchema` accepts JSON numbers only, so `''`, `' '`, `'13'`, `true` and `[5]` are refused.
- **REV-0199, LOW, editor.**
  - Both pin buttons stay disabled until something is typed, so opening the editor never turns the sheet markup into this row's own.
  - Changing the cost filter clears the ticked rows.
  - The refusal tests now assert the exception type.
  - Added a test for "pin and apply" ending in CURRENT.
- **REV-0200 (visual).**
  - The form uses `noValidate`, so the panel's translated error shows instead of the browser's bubble.
  - `$` amounts and SKUs inside sentences are isolated with LRI/PDI, in both the admin and the API's Arabic error.
  - The sticky editor has an inline gutter.
  - The below-cost note wraps.
  - A proposal at or under cost is flagged in the preview.
  - Touch targets at 768 stay as they are on every other supplier tab. They are 44 px only at ≤640 px, so this is not changed here.
- **REV-0201 (qa-lead re-check), FAIL, markup in the band.** Under WHOLE and END_99 the price was right, but the pinned markup was the edge of the band of markups making that price, not the typed percentage.
  - The search now also starts from the typed price's own percentage and from both edges of each band.
- **REV-0203 (re-check), CONCERN, high multiples.** Above 11× cost on tiny costs, the search could return null where 1000% makes the nearest price.
  - Search anchors are now clamped into 0–1000%.
  - A typed price beyond the 1000% price by half a rounding step or more is refused (null, then 400) rather than silently pinned at 1000%.
  - Exhaustive integer oracle (every 0.01% from 0 to 1000%): 2,688 cases in all three roundings, 0 mismatches, of which 768 are correct refusals.
- **REV-0202 (visual re-check), CONCERN.**

  - The Arabic terms are isolated from the SKU in the product cell.

- **Accepted.** Pin then apply is not one transaction. A skipped apply leaves the markup pinned, and the panel says why it was not applied.
