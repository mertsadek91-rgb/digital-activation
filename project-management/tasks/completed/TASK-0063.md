## Implementation plan

The objective as written (a cookie-presence check in `proxy.ts`) cannot be met
in the current topology: `da_access` / `da_refresh` are host-only cookies on
`api.` (no `Domain` in `auth.controller.ts` `setCookies`), so the admin origin's
proxy never receives them. Options are in the 2026-09-30 06:20Z note: (a) serve
the API through the admin origin, (b) rejected, (c) one shared client hook.

(c) is what is in the code: every protected page gets its session through
`apps/admin/src/lib/use-staff.ts` (directly, via `content/shared.tsx`, or via
`marketing/signals-shared.tsx`). REV-0089 / REV-0090 recommend completing with
scope narrowed to (c) — pm-04's call, owner informed — and (a) only as a new
task. That call has not been recorded yet; nothing here pre-empts it.

## Problems discovered

- **Metadata (REV-0089/0090):** `affected_files` still lists only
  `apps/admin/src/proxy.ts`, which (c) does not touch. Changing it is a `pm`
  write; left for pm-04 together with the scope call.
- **Role gating is READONLY-only, by design.** `canOpen` restricts READONLY

  must (TASK-0095). Content and marketing pages call `useStaff()` without a
