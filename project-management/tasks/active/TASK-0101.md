## Diagnosis (from the CI Lighthouse reports on `main` at 1a0a189, 2026-10-05)

Mobile, five pages: performance 0.71–0.92, requests 65–80 (budget 60),
LCP 3.1–3.4 s simulated, cart CLS 0.41, render-blocking on the collection and
the cart. The observed (unthrottled) LCP in CI was 155–194 ms on every page:
the simulated number is Lighthouse's model of _bytes before LCP_ over slow
4G — document 37 KB, CSS 24 KB, nine font files 126 KB, fourteen scripts
311 KB — so the levers are bytes and request count, not paint order.

What the requests were:

- 35–43 per page were `?_rsc=` link prefetches: Next prefetches every
  `<Link>` in view, and every page renders per request with no
  `loading.tsx`, so each prefetch fetched a 1–2 KB layout shell the
  navigation cannot use. Two passes per link.
- A 107 KB chunk on every page: `@da/contracts` compiled as CommonJS, with
  zod and all its locales. → TASK-0105.
- A 28 KB chunk on every page, 100% unused: the client 404 page imported
  both message catalogues, and a not-found boundary travels with its layout.
- Nine font files: Tajawal in four weights × two subsets, plus Inter. The
  800 weight was used by nine headings the UI Kit sets at 700.
- CORS preflights on every cart GET (a `content-type` header on a GET),
  `currencies` fetched twice (two switchers), `payment-methods` twice on the
  cart, framer-motion (45 KB) on the product page for a slide and a fade.
- Cart CLS 0.41: the footer painted on screen and was pushed off when the
  cart lines arrived.

## Changes

- `src/components/link.tsx`: `next/link` with `prefetch={false}`; every
  storefront import points at it (lint rule in `eslint.config.mjs`).
- `src/lib/cart-client.ts`: content type only when there is a body.
- `currency-switcher.tsx`, `product-trust.tsx`: one fetch per page load,
  shared by every instance.
- `[locale]/layout.tsx`: Tajawal 400/500/700; the nine `font-weight: 800`
  rules became 700 (account, catalog, contact, warranty CSS).
- `not-found-page.tsx` + `[locale]/not-found.tsx`: the `notFound` namespace
  of both catalogues comes down as props from the server component.
- `cart/page.tsx` + `cart.css`: `.cart-main { min-block-size: 100dvh }` on
  all three states.
- `buy-box.tsx` + `catalog.css`/`cart.css`: the sticky buy bar is always in
  the document and slid by the existing CSS transition (`inert` when
  hidden); the "added" notice is a CSS keyframe. `framer-motion` removed
  from the storefront's dependencies.
- `mock/api.mjs`: `MOCK_CART=1` answers a one-line cart, so `/cart?add=` can
  be measured locally the way CI measures it.

## Measurement

Local runs use the same CLI pin and `lighthouserc.json` as CI against a
production build and the mock API. They are only comparable with each
other: this machine's antivirus injects a script into every HTTP page and
strips the compression, so the document arrives at 246 KB instead of 37 KB
and the absolute LCP is about 2 s worse than CI's. Relative, home page
mobile: requests 68 → 39, scripts 431 KB → 238 KB (uncompressed transfer),
fonts 9 → 7, cart CLS 0.39 → 0. CI is the number that counts; see the PR.
