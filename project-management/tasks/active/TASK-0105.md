# TASK-0105 — Publish @da/contracts as ESM with sideEffects:false so the apps tree-shake it (the CommonJS build put the whole package into the storefront client bundle)

## Objective

## Notes

The storefront's largest client chunk (107 KB gzipped, 552 KB raw, loaded by
every page) turned out to be `@da/contracts` plus zod. The package was
compiled to CommonJS (`module: NodeNext` without `"type": "module"`), and a
CommonJS module cannot be tree-shaken: every schema in the package, and zod
with all 253 of its error-message locales, went to the browser whether a
page used them or not.

Two changes, both to how the package is delivered, none to its API:

1. `packages/contracts/package.json`: `"type": "module"` and
   `"sideEffects": false`. `tsc` with `NodeNext` then emits ESM; the
   `exports` map is unchanged. The CommonJS consumers (the API, `@da/db`
   scripts) load it through Node's `require(esm)`, which is unflagged from
   Node 22.12 — the version `engines` already demands.
2. `patches/zod@4.5.4.patch` (pnpm `patchedDependencies`): removes the two
   `export * as locales` namespace re-exports. Turbopack does not shake a
   namespace re-export even with `experimental.turbopackRemoveUnusedExports`
   (tried, no change); webpack and Rollup do, which is why zod ships it this
   way (zod#6050, zod#6633, closed "not planned"). Nothing in this repository
   reads `z.locales`; the locales stay importable from `zod/locales`. The
   patch is pinned to 4.5.4, so a zod bump fails `pnpm install` until
   someone re-reads it.

Result on the home page: the chunk went from 107 KB to 50 KB gzipped (zod
core plus the schemas the client actually imports); scripts per page from
311 KB to 238 KB.
