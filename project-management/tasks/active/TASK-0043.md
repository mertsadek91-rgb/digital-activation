# TASK-0043 — Which legacy customers, orders and keys migrate

## Task objective

Decide the migration scope for the only legacy data that has not moved. This is
the owner's decision.

## Current state (verified 2026-09-29)

- **Already migrated:**
  - catalogue: 101 variants and 105 LegacyMap rows
  - pages and articles
  - 102 migration redirects
  - media (52 assets)
- **Not migrated:** customers, orders, delivered keys and account credentials.
- **Where the unmigrated data is:** only in the SQL dump and the live WordPress
  database. The XML export has none of it.
- **What exists in the new database today:** demo data only (BUG-0016).

## Options

- **A. Migrate everything.** Customers find their past orders and keys in the new
  portal. Requires the extraction and scrub procedure (CONSENSUS-0002).
- **B. Customers and order history only, no secrets.** Past keys and credentials
  are re-sent from the old system or on request, and the plaintext is scrubbed
  without being moved.
- **C. Migrate nothing.** The new store starts clean. Past buyers are pointed to
  support. The SQL dump stays archived until the old site is retired.

The choice decides whether the SQL dump and tarball are still needed
(CURRENT_STATE_AUDIT.md §7).
