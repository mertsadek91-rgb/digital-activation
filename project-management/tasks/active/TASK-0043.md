# TASK-0043 — Which legacy customers, orders and keys migrate

## Task objective

Decide the migration scope for the only legacy data that has not moved. This is
the owner's decision.

## Current state (verified 2026-09-29)

- **Already migrated:**
  - catalogue: 101 variants and 105 LegacyMap rows
  - pages and articles
  - 102 migration redirects
  - media (52 assets)
- **Not migrated:** customers, orders, delivered keys and account credentials.
- **Where the unmigrated data is:** only in the SQL dump and the live WordPress
  database. The XML export has none of it.
- **What exists in the new database today:** demo data only (BUG-0016).

## Options

- **A. Migrate everything.** Customers find their past orders and keys in the new
  portal. Requires the extraction and scrub procedure (CONSENSUS-0002).
- **B. Customers and order history only, no secrets.** Past keys and credentials
  are re-sent from the old system or on request, and the plaintext is scrubbed
  without being moved.
- **C. Migrate nothing.** The new store starts clean. Past buyers are pointed to
  support. The SQL dump stays archived until the old site is retired.

The choice decides whether the SQL dump and tarball are still needed
(CURRENT_STATE_AUDIT.md §7).

## Decision brief (prepared 2026-10-07)

> Prepared by an agent from code, schema and project records only. No legacy
> data was opened. **Nothing here is approved; the choice is the owner's.**
> Not legal advice: the PDPL points below need confirmation by counsel.

### The question

Which legacy WordPress data moves into the new store before cutover: customer
accounts, order history, and the licence keys / Office 365 and Adobe account
credentials that staff pasted into order notes in plaintext (BUG-0014/0015)?

### Known facts (from records, not from the data)

- Volumes in the records (plan, 2026-09 audit): ~224 customers, 185 orders
  (124 completed, 59 cancelled, 2 refunded; one currency, one manual gateway),
  55 keys in `wc_ld_license_codes`, the rest only in order notes. **Current
  counts must come from the owner or an approved task**; the dump is dated
  2026-09-08, so every order placed since then exists only in live WordPress.
- Customers sign in by magic link (`Customer.passwordHash` is null for migrated
  customers). WordPress password hashes are never needed: "forced reset" means
  nothing to reset (TASK-0041 re-audit).
- The schema is ready for most of it: `LegacyMap` already lists the `customer`,
  `order` and `license_code` types; `OrderItem` takes snapshots and
  `assignedKeyIds`; vault `LicenseKey` has `ACCOUNT_CREDENTIALS`, `fingerprint`
  and `orderItemId`. **Gaps:** no "legacy" marker on Order and no legacy
  `PaymentProvider`, so a new migration is needed; `OrderItem.variantId` is
  required, so lines for products no longer in the catalogue need a mapping rule.
- Side effects: the renewal-reminder sweep (`apps/api/src/retention/`) and the
  review-invite sweep (`apps/api/src/reviews/`) email real customers. Imported
  orders must be excluded from both, or old buyers get mail on day one.
- Importers exist only for catalogue, pages, articles, redirects and media (dry-run
  by default). There is no customer, order or key importer.

All import options write to the database that becomes production in place
(DEC-0011), so each `--apply` needs an approved task (CLAUDE.md rule 3).

### Recommendation (agent recommendation, not a decision)

**Option B**, imported as read-only legacy records excluded from renewal,
review and marketing mail, from a fresh export taken at cutover. Licence keys
are re-sent by support on request from the legacy source during a fixed window
(suggested 90 days). Account credentials (Office 365 / Adobe) are **not**
migrated in any option: they are rotated or re-issued on request. At the end of
the window the owner runs a recorded scrub and destruction of the plaintext.
Move to A only if the owner expects many key requests, because A is the single
largest piece of remaining migration work.

### Answers needed from the owner

1. Which option: C, D, B or A?
2. Which orders: completed and refunded only, or cancelled ones too (59)?
3. Will a fresh export be taken at cutover to catch orders after 2026-09-08,
   and who takes it?
4. Account credentials: migrate (A only), or rotate / re-issue on request?
5. Support window for key look-ups: how long, and on what date are live WP
   order notes and the SQL dump scrubbed and destroyed, and by whom?
6. Notify legacy customers of the move and the updated privacy notice: yes / no?
7. Should legacy customers ever receive renewal reminders or review invites?
8. Will counsel confirm the PDPL position (and any other law that applies to the
   trading entity) before import?
