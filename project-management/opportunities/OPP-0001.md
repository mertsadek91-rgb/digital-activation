# OPP-0001 — One source of truth for the store's official channels

<!-- Opportunity Development Pack. Every "##" section below is required before READY_FOR_OWNER_DECISION; see agent-os/PRODUCT_EVOLUTION_OPERATING_MODEL.md. -->

## Executive Summary

The footer of every storefront page, in both languages, sits under the heading
"قنواتنا الرسمية" ("our official channels"). Several of those channels are not
real:

- **Instagram** opens instagram.com's login wall instead of a profile.
- **X** links to an account that appears to belong to someone else.
- **Telegram:** the site shows two different handles, and neither matches its
  label.

The Organization structured data, meanwhile, declares no profiles at all.

The fix is small (LOW complexity, no API or schema change). Keep one list of
verified profiles in `apps/storefront/src/lib/contact.ts`, the module that
already holds the phone and email, and feed both the footer and `sameAs` from
it.

It is **blocked on the owner** confirming which handles the store actually
owns. Until then, the honest interim step is to show only WhatsApp and email.

(SIG-0002).

## Problem

A buyer paying for licence keys often checks whether the seller is legitimate
before paying (INFERENCE), because this is a category with grey-market sellers.
The footer answers that check with channels labelled "official":

- The Instagram button (`site-footer.tsx:188`) opens `https://instagram.com`.
  It is labelled "Instagram Profile", but no profile exists at that address
  (FACT).
- The X button links to `x.com/digital_activ`. When the UX shaping agent opened
  it, that account was named "DIGITAL ACTIVITY", had joined in 2011, had 2
  followers and had never posted (OBSERVATION; not re-verified by the lead).
- **Telegram (FACT):**

  | Where               | Handle                    |
  | ------------------- | ------------------------- |
  | Footer              | `t.me/digitalactivation`  |
  | Contact page, seeds | `t.me/digitalactivations` |

- The Organization JSON-LD passes `sameAs: []` (`layout.tsx:112`, FACT).
- The seed's unused `SeoSetting` row lists yet another set of handles
  (`seed.ts:371-393`, FACT).

The store currently makes a claim a buyer can disprove in one click.

## Evidence Against

- **Google does not guarantee** that structured data changes anything shown in
  search results (FACT; sd-policies, accessed 2026-09-29).
- **No primary source says `sameAs` improves ranking.** A Google employee said,
  as reported second-hand, "structured data won't make your site rank better."
  Treat this as identity hygiene, not a growth lever.
- **Knowledge panels are generated automatically** once enough information exists
  on the open web. A new, small store is unlikely to get one either way
  (FACT + INFERENCE).
- **Small or dormant profiles add little.** If the owner cannot confirm active
  official profiles, `sameAs` stays empty and the SEO half of this opportunity
  is worth close to nothing (INFERENCE).
- **There is no baseline.** Nothing measures footer clicks or trust today
  (SIG-0005), so the user-value estimate is unmeasured.

## Current UX

The footer's brand column shows "قنواتنا الرسمية:" followed by, in RTL order:

1. WhatsApp: works
2. Telegram: a personal contact labelled "channel"
3. X: an unrelated dormant account
4. Instagram: a login wall
5. Email: works, but its paper-plane icon looks like the Telegram mark

The label is a `span`, not a group label. The icons are not a list. There is no
warning that links open a new tab, and the Arabic page carries redundant
English `title`s.

## Proposed UX

**Direct support first:** WhatsApp, then email.

**Then only verified profiles.** An entry with no URL renders nothing; the site
never falls back to a network's home page.

- **Labels:** accurate, e.g. "تيليجرام الدعم" (Telegram support) for a contact
  account; "قناة" (channel) only for a real channel. The heading reads
  "تواصل معنا وتابعنا" ("contact and follow us") until every link is verified.
- **Markup:** `rel="me noopener noreferrer"`, 44 px targets, a list with
  `aria-labelledby`, and an envelope icon for email.
- **Direction:** DOM order is kept, so RTL flips it naturally. The icons
  themselves are not mirrored.

## Product Solution

Add a typed `OFFICIAL_PROFILES` list (network, url, label key) to
`apps/storefront/src/lib/contact.ts`. That module already describes itself as
"the store's real contact channels, in one place", and the header, WhatsApp
button and layout JSON-LD already import from it.

The following read from the list:

- the footer
- the contact page, which removes its own copies of the channel details
- `jsonld.organization({ sameAs })`

The copies of the WhatsApp number and support email in `site-footer.tsx`,
`contact/page.tsx`, `golden-warranty/page.tsx` and `global-error.tsx` are
replaced with imports from the same module.
